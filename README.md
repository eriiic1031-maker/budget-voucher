# 예산 및 전표관리 (샘플)

총무 담당자용 샘플 프로그램. 메일·홈택스로 받은 전자세금계산서를 계정·부서·사용자별로 자동 분류해 SAP 전표(BAPI_ACC_DOCUMENT_POST, 모의)를 만들고,
**정기·비정기 전표 점검**과 **총무 예산 대비 초과(예상) 경고와 그 이유**를 보여준다.

> 테스트 순서는 별도 문서 "예산 및 전표관리 테스트 가이드"를 따라가면 된다.

## 빠른 시작

```bash
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m voucher.seed               # 예시 데이터: 2025-01~2026-10 세금계산서 약 1,700건(월 70~80건, 2025년 약 120억) + 예산
.venv\Scripts\python -m streamlit run streamlit_app.py  # http://localhost:8501
.venv\Scripts\python -m pytest -q                  # 자동 테스트
```

## 화면 보기 (로그인 없음)

샘플이라 로그인이 없다. 처음엔 **총무 담당자(관리자)** 화면으로 열리고, 사이드바 **화면 보기**에서 다른 사람 화면으로 바꿔 볼 수 있다.

| 사람 | 권한 | 부서 |
|---|---|---|
| 총무 담당자 (`admin`) | 관리자 | 총무팀 |
| 홍길동 (`E1023`) | 사용자 | 영업1팀 |
| 김철수 (`E2045`) | 사용자 | 물류팀 |

| 기능 | 사용자 | 관리자 |
|---|:-:|:-:|
| 대시보드 (사용자는 우리 부서 기준) | ✅ | ✅ |
| 총무 예산 (경고·연간·예산 입력) | - | ✅ |
| 전표 점검 (정기·비정기) | ✅ | ✅ |
| 검토 건 분개 수정 | ✅ → 승인 요청 | ✅ → SAP 전기 / 반려 |
| 부서별 비용 | 우리 부서 | 전체 부서 |
| 홈택스 대사, 기준정보, 사용자 관리 | - | ✅ |

> 운영 전환 시에는 사내 SSO(`st.login` + OIDC) 등으로 로그인을 붙이고 '화면 보기' 전환은 없애야 한다.
> `voucher/auth.py` 의 비밀번호 해시·권한 함수는 그대로 쓸 수 있다.

## AI 도우미 (로컬 AI · Ollama)

회사 재무 데이터가 외부로 나가지 않도록 **내 PC의 Ollama**만 씁니다. 금액 계산·분개·전기·예산 예측은 지금처럼 코드가 하고,
AI는 **판단과 문장**만 맡습니다. AI가 없거나 실패하면(메모리 부족, 클라우드 데모 등) **규칙·과거 기록 방식으로 자동 대체**되어
화면과 기능은 같습니다.

| 기능 | 위치 | AI가 하는 일 | AI가 없을 때 |
|---|---|---|---|
| 계정·부서 추천 | 검토·전기 (규칙 없는 건) | 과거 비슷한 처리 사례 + 계정·부서 목록을 보고 고르고 이유 작성 | 비슷한 과거 건 다수결 |
| 추천 정확도 | AI 도우미 › 추천 정확도 | 추천과 최종 전기 결과를 비교 기록 | 동일 |
| 총무 예산 브리핑 | AI 도우미 › 총무 브리핑 | 계산된 사실(JSON)만으로 보고 문장 작성 | 문장 틀 |
| 질문하기 | AI 도우미 › 질문하기 | 정해 둔 조회 함수 중 하나를 고르고 결과로만 답함 | 키워드로 조회 함수 선택 |
| 문서 읽기 | AI 도우미 › 문서 읽기 | 고지서·청구서 이미지에서 금액·기한·항목 추출 → 연간 항목 처리 | PDF 글자층에서 규칙으로 추출 |
| 이상 신호 | AI 도우미 › 이상 신호, 대시보드 카드 | (설명 문장) | 규칙으로 탐지: 중복·분할 의심, 금액 급증, 신규 고액 |

**켜는 방법**
1. https://ollama.com 에서 Ollama 설치
2. 모델 받기: `ollama pull qwen2.5vl:3b` (글·이미지 모두, 약 3.2GB)
3. 앱의 AI 도우미 화면에서 **연결 다시 확인** → 배지가 '로컬 AI 연결됨'으로 바뀜

- 다른 모델은 `.env` 의 `OLLAMA_MODEL` 로 바꿉니다. 항상 규칙 방식으로 쓰려면 `AI_MODE=off`.
- 모델을 불러올 메모리(가상 메모리 포함)가 부족하면 실패하고 10분간 규칙 방식으로 동작합니다.
- 문서 읽기 예시 파일: `docs/sample_전기안전점검_청구서.pdf`

## 총무 예산

- **총무 예산 계정**: 기준정보 > 계정의 `예산 주관`이 `총무`인 계정만 대시보드·부서별 비용·예산 화면에 나온다
  (데모: 임차료·관리비·수도광열비·통신비·렌탈·차량리스·차량유지·복리후생·용역·소모품·수선비 / 운반비·광고·교육·IT 수수료는 제외)
- **월별 예산**: 총무 예산 > 예산 입력 (계정 × 12개월). "작년 실적 × 1.05로 채우기" 버튼 제공
- **월말 예상** (`voucher/budget.py`)
  = 받은 정기 전표 + **아직 안 받은 정기 전표 추정**(작년 같은 달 금액 × 올해 단가 비율 → 계절성 반영)
  + **큰 비정기 건**(예산 5% 또는 300만원 이상, 한 번만 반영)
  + 나머지 비정기 = 지금까지 + 남은 기간 × [경과율×이번 달 속도 + (1-경과율)×작년 같은 달×올해 추세]
- **경고 단계**: 🔴 초과(이미 사용 > 예산) · 🟠 초과 예상(예상 > 102%) · 🟡 주의(98~102%)
- **이유 문장**: 큰 비정기 지출, 미수신 정기 전표 예정액, 정기 전표 금액 증가(단가·요금 인상), 작년 대비 지출 속도,
  올해 증가 추세, 작년 실적보다 낮게 잡힌 예산, 전기 전 금액 포함 여부

## 전표 점검

| 구분 | 확인 내용 |
|---|---|
| 정기 전표 | 매달 들어와야 하는 전표의 기한·금액 (기한 경과 / 금액 상이 / 수신·미전기 / 수신 대기) |
| 비정기 전표 | 금액·용도·부서를 담당자가 눈으로 확인 → 여러 건 선택 후 "확인 완료" (💰 300만원 이상, 🆕 최근 3개월 신규 거래처 표시) |

## 흐름

```
메일(IMAP) XML 첨부 ─┐
홈택스(팝빌 API)     ─┤
폴더/수동 업로드      ─┼─▶ 파싱 ─▶ 승인번호 중복제거 ─▶ 분류(규칙) ─▶ READY ─▶ SAP 전기
관리자 페이지 업로드 ─┘                                      └▶ REVIEW ─▶ 담당자 수정 ─┘
```

| 단계 | 파일 | 내용 |
|---|---|---|
| 수집 | `voucher/mail.py`, `collect.py` | 안 읽은 메일의 `.xml`/`.zip` 첨부 → `data/inbox/YYYYMM/` 보관 |
| 홈택스 | `voucher/hometax.py` | 팝빌 API로 매입 목록 수집 → 미수집 건 XML 자동 등록 → 대사 |
| 파싱 | `voucher/parser.py` | 국세청 표준 XML (승인번호, 공급자, 품목, 금액, 수정세금계산서 구분) |
| 분류 | `voucher/classifier.py` | 품목별 계정 규칙 → 차량번호/배부기준/코스트센터로 부서·사용자 분할 |
| 전표 | `voucher/sap.py` | BAPI 페이로드 생성. `SAP_MODE=mock`은 로컬 발번, `rfc`는 pyrfc로 CHECK→POST→COMMIT |
| 점검 | `voucher/recurring.py` | 월별 정기 전표 상태: 전기 완료 / 금액 상이 / 수신·미전기 / 수신 대기 / 기한 경과 |
| 화면 | `streamlit_app.py`, `app_pages/` | 대시보드, 정기 전표 점검, 검토·전기, 홈택스 대사, 조회, 기준정보 |

## 홈택스 대사 — 무료 방법 (엑셀 업로드) ⭐ 기본

API 계약 없이 **홈택스에서 직접 내려받은 엑셀**로 같은 대사를 한다.

1. 홈택스 로그인 → 전자(세금)계산서 **목록조회** → **매입** 선택 → 기간 조회 → **엑셀내려받기**
2. 홈택스 대사 화면 > "홈택스 엑셀 올리기" 탭에 파일을 그대로 업로드
3. 시스템에 없는 건은 자동 등록 → 규칙대로 분류 → 검토·전기

- `voucher/hometax_excel.py` 는 컬럼 **이름**으로 찾으므로 제목줄 수·컬럼 순서가 바뀌어도 동작 (`.xlsx`, `.xls`, `.csv`, `.xls` 확장자의 HTML 표 지원)
- 엑셀에는 품목이 대표 1건만 있는 경우가 많아 1줄짜리 세금계산서로 등록된다. 계정을 나눠야 하면 검토 화면에서 행을 추가
- 예시 파일: `samples/홈택스_매입목록_예시_202610.xlsx` (메일로 안 온 2건 포함)
- **주의**: 홈택스 화면 개편 시 컬럼명이 바뀔 수 있다. 실제 파일을 처음 올릴 때 "인식한 컬럼"을 확인하고, 필수 컬럼(승인번호·작성일자·공급자 사업자등록번호·합계금액)을 못 찾으면 오류 메시지에 인식된 컬럼 목록이 표시된다 → `FIELDS` 후보명에 추가
- 월 1회(부가세 신고 전) 또는 주 1회 올리는 것을 권장

| 방법 | 비용 | 자동화 | 비고 |
|---|---|---|---|
| 메일 XML 수집 | 무료 | 자동 | 메일 안 보내는 공급자 누락 |
| **홈택스 엑셀 업로드** | **무료** | 수동(월·주 1회) | 누락 탐지·보완, 품목 1건 |
| 팝빌 등 ASP API | 유료(정액제) | 완전 자동 | 원본 XML까지 수집 |

> 홈택스 화면을 프로그램으로 자동 조작(스크래핑)하는 방식은 인증서·약관·차단 위험이 있어 권장하지 않는다.

## 홈택스 연동 (팝빌, 유료 선택)

메일 수집은 공급자가 메일을 안 보내거나 조회 링크만 보내면 놓친다. 홈택스에는 발행된 매입 세금계산서가 **모두** 있으므로
`voucher/hometax.py` 가 기간별 매입 목록을 받아 시스템과 승인번호로 대사하고, 시스템에 없는 건은 XML을 내려받아 같은 분류·전기 흐름에 넣는다.

| 대사 결과 | 의미 | 조치 |
|---|---|---|
| 일치 | 홈택스·시스템 모두 있음, 금액 같음 | - |
| 시스템 미수집 | 홈택스에만 있음 (메일 미수신) | 수집 시 자동 등록 → 검토·전기 |
| 금액 불일치 | 승인번호 같은데 금액 다름 | 원본 확인 |
| 홈택스 미확인 | 시스템에만 있음 | 수집 기간 확인, 취소·위조 여부 확인 |

**연결 절차** (팝빌 가입·인증서 등록·결제는 담당자가 직접)

1. [팝빌 개발자센터](https://developers.popbill.com)에서 연동 신청 → `LinkID`, `SecretKey` 발급
2. `.env` 에 `HOMETAX_PROVIDER=popbill`, `POPBILL_LINK_ID`, `POPBILL_SECRET_KEY` 입력 (`POPBILL_IS_TEST=true` 로 먼저 테스트)
3. 팝빌에 회사 연동회원 가입 후 **홈택스 인증서** 또는 **홈택스 부서사용자 계정** 등록
   - 관리자 페이지 > 홈택스 대사 > 팝빌 연동 상태 > "홈택스 인증서 등록" 버튼으로 팝업을 열 수 있음
4. 팝빌에서 **홈택스 수집 정액제** 신청 (유료)
5. 관리자 페이지에서 "홈택스 수집" 실행, 또는 작업 스케줄러에 `collect.py --hometax` 하루 1~2회 등록 (전월+당월 수집)

> 운영 서버로 바꿀 때는 `POPBILL_IS_TEST=false`. 팝빌은 기본적으로 호출 IP를 제한하므로 서버 IP를 팝빌에 등록해야 한다.

## 분개 규칙

```
(차) 비용계정 (코스트센터·사용자별)   공급가액        ← 불공제면 세액 포함, 세금코드 V3
(차) 부가세대급금                     세액            ← 세금코드 V1 합산
    (대) 공급업체                     합계금액
```

- **계정**: `account_rules`를 우선순위 순으로 (공급자 사업자번호, 품목 키워드)에 매칭
- **귀속**: ① 품목·비고에 차량번호가 있으면 `vehicles` → ② 규칙의 배부기준 `allocation_keys` 비율 분할 (끝수는 마지막 라인) → ③ 규칙의 코스트센터
- **사용자(사번)**: SAP 지정필드(ALLOC_NMBR)에 기록
- **수정세금계산서**(마이너스): 부호 반대, 전표유형 KG
- 규칙이 없거나 공급업체 미등록, 금액 불일치 → **검토 대기**. 검토 화면에서 고치면서 "공급자 규칙으로 저장"하면 다음부터 자동 분류

## 운영 전환 체크리스트

1. `.env.example` → `.env` 복사 후 회사코드, 세금코드, 부가세대급금 계정을 **실제 SAP 설정에 맞게** 변경
   - 불공제 처리 방식(V3 세금코드로 SAP가 자동 처리 vs 비용에 직접 가산)은 FI 담당과 확인 필요. 현재는 비용에 가산.
2. 기준정보: 공급업체(사업자번호 → LIFNR), 계정 규칙, 배부기준, 차량, 정기 전표 등록
3. SAP 연결: NW RFC SDK + `pip install pyrfc`, RFC 사용자에 `F_BKPF_*` 권한, `SAP_MODE=rfc`
